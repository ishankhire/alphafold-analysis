# Project Orientation Summary

A high-level orientation to the project and the two output directories currently in
focus. Written as a quick-reference map, not an exhaustive record.

## What the project does

Mechanistic interpretability on **AlphaFold2 pair representations** — the
`(R, R, 128)` tensors at each of the 48 Evoformer layers. The core method: train
**linear probes** that predict pairwise C-alpha distances (from predicted PDBs)
out of the 128-channel pair features, then track how that decodable distance
signal builds up across network depth. Outputs are R² curves, reconstructed
geometry (MDS → TM-score), and coefficient analyses.

## The two directories currently in focus

Both run on the **combined CAMEO + ECOD pool** (552 loaded / 554 discovered
proteins, TM-score > 0.7) with **256-d "base256" features** =
`[pair(i,j), pair(j,i)]`, across all 48 layers.

### `delta_files/general_base256_combined`
One **shared** train/test model (441 train / 111 held-out, 80/20 size-stratified,
seed 42). This is the generalizing probe.
- Held-out R² climbs from ~0.49 (L0) to a peak **0.9406 at L44**.
- Held-out TM-score peaks **0.8693 at L45**.

### `delta_files/per_protein_base256_combined`
One model fit **per protein** on all of that protein's pairs (assembled from
layer-window shards `00_09 … 40_47`, then merged). Higher ceiling, as expected —
this is the "how much distance is linearly present" upper bound.
- R² peaks **0.9876 at L45**.
- TM-score peaks **0.9423 at L46**.

### Shared layout
Each directory holds the standard schema: `per_protein.csv`, `coefficients.csv`,
`geometry_metrics.csv`, `split_summary.csv`, `summary.txt`, plus an `analysis/`
subdir of plots and a markdown report. Those are generated by local scripts in
`scripts/multi_protein/regression/`:
- `analyze_delta_general_base256_combined.py`
- `analyze_delta_per_protein_base256_combined.py`
- `analyze_delta_base256_variants.py` (cross-variant comparison)

## Most recent thread — exact triangle-inequality violations

A 48-task Delta layer-array replay (`scripts/cluster_scripts/generalized_model_ecod/`)
reuses saved base256 coefficients to recompute geometry and now writes **exact**
unordered-triangle metrics per protein: violation fraction plus severity bins
(`0_5`, `5_10`, `10_plus`) →
`delta_files/general_base256_combined/exact_triangle_metrics/exact_triangle_metrics.csv`,
analyzed locally by `analyze_delta_exact_triangle_metrics.py`. There is also a
sampled-triangle variant (2,000 held-out triples for layers 0/10/20/30/40/47) in
`triangle_violation_samples_test/`. This replaced the older aggregate-only
`triangle_violation_*` fields.

## Conventions internalized

- **float64** for dense linear fits / least-squares / PCA on pair-block features
  (float32 is opt-in; it was shown to be numerically pathological at scale).
- Hot per-layer pair-block extraction: plain `np.load(...)` + direct preallocated
  writes (not `mmap_mode="r"` + repeated `np.concatenate`).
- Cluster scripts: per-layer output checkpointing + timestamped stdout logging.
- Fixed script configuration (no CLI args unless genuinely required).
- Cluster target is **Delta** only; consult `proteins/llm_reference/` PDFs for
  SLURM specifics.
- Log substantive changes to `branch-analysis.md`; commit + push frequently.
- Dataset source of truth: `datasets.md` (combined CAMEO + ECOD, TM > 0.7).
